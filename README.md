# KulshAI

Веб-чат в стиле Material Design 3 с несколькими LLM-провайдерами: тёмная/светлая
тема, переключение языка (RU/EN), вложения (изображения, ZIP, текстовые файлы),
голосовой ввод/озвучка через браузер, история чатов в localStorage, рендеринг
Markdown (таблицы, код, списки и т.д.), общий суточный лимит токенов, скиллы и
публичные страницы (лендинг, «О Kulsh», документация API).

Модели двух провайдеров:
- **Google Gemini** — нативный API, ротация ключей `APIKEY1..APIKEY5` при 429/5xx.
- **NeutralBeats** — [OI]-совместимый API, один ключ `NEUTRALBEATS_API_KEY`.

## Деплой на Vercel

1. Залей эту папку в GitHub-репозиторий (или используй `vercel` CLI прямо из папки).
2. На [vercel.com](https://vercel.com) — "Add New Project" → выбери репозиторий.
3. Vercel сам определит статику в `public/` и функции в `api/` — **build command не нужен**.
4. Перед первым деплоем добавь переменные окружения (см. ниже).
5. Нажми Deploy.

## Переменные окружения (обязательно)

В настройках проекта на Vercel → **Settings → Environment Variables** добавь:

| Имя                     | Значение                                              |
|-------------------------|-------------------------------------------------------|
| `APIKEY1`               | API-ключ Gemini участника команды №1                  |
| `APIKEY2`               | API-ключ Gemini участника команды №2                  |
| `APIKEY3`               | API-ключ Gemini участника команды №3                  |
| `APIKEY4`               | API-ключ Gemini участника команды №4                  |
| `APIKEY5`               | API-ключ Gemini участника команды №5                  |
| `NEUTRALBEATS_API_KEY`  | API-ключ NeutralBeats (модели DeepSeek / GLM / Kimi)  |

Ключи Gemini получаются в [Google AI Studio](https://aistudio.google.com/apikey) —
каждый участник команды создаёт свой ключ на своём личном аккаунте Google.
Ключ NeutralBeats выдаётся в личном кабинете NeutralBeats.

Можно указать от 1 до 5 ключей Gemini — сервер сам подхватит только заполненные.
При ошибке 429 (превышен лимит) или 5xx на одном ключе сервер автоматически
пробует следующий по списку, так что для пользователя сайта сбой одного
ключа останется незаметным, пока не исчерпаны все.

Дополнительные (необязательные) переменные:

| Имя                       | Значение |
|---------------------------|----------|
| `NEUTRALBEATS_BASE_URL`   | Другой base URL NeutralBeats, если нужен (по умолчанию `https://api.neutralbeats.com/v1`) |
| `SITE_URL`                | Основной адрес сайта (для OAuth за прокси / на превью-деплоях) |

Переменные для входа (`AUTH_SECRET`, `TELEGRAM_BOT_TOKEN`, `GITHUB_*`, `GOOGLE_*`)
и для базы (`KV_REST_API_URL` / `KV_REST_API_TOKEN`) — см. разделы ниже.

**Важно:** после добавления/изменения переменных окружения нужно сделать
redeploy проекта (Vercel не подхватывает новые env-переменные "на лету"
для уже собранного деплоя).

## Вход через аккаунт (Google / GitHub / Telegram)

Всё бесплатно, без почты и без обязательной базы данных. Сессия — подписанная
HttpOnly-cookie (30 дней), в ней только id, имя и аватар из выбранного сервиса.
База (Upstash Redis) нужна только для синхронизации чатов, лимитов и скиллов —
подробнее в разделе «Хранение чатов и настроек».

**Что видит гость (без входа):** только `gemini-3.5-flash-lite`, один чат,
без вложений, без своих инструкций и настройки креативности, контекст — последние
20 сообщений. Это проверяется и на сервере (`api/chat.js`), а не только в интерфейсе.
**После входа:** все модели, новые чаты, вложения, свои инструкции.

Включай только те способы, что нужны: кнопка появляется, когда заполнены её переменные.
После любых изменений переменных на Vercel сделай **Redeploy**.

### 0. Общее (обязательно)

| Переменная    | Значение |
|---------------|----------|
| `AUTH_SECRET` | Любая случайная строка от 32 символов. Получить: `openssl rand -base64 32` или в консоли браузера `crypto.randomUUID()+crypto.randomUUID()` |
| `SITE_URL`    | *(необязательно)* Основной адрес, напр. `https://kulsh.vercel.app`. Нужен, если у сайта несколько доменов или он за прокси |

Ниже `ТВОЙ-ДОМЕН` — адрес сайта без слэша на конце, например `kulsh.vercel.app`.

### 1. Telegram (самый простой, ~2 минуты)

1. В Telegram открой [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя и username → получишь **токен** вида `123456:ABC-DEF...`.
2. Там же: `/setdomain` → выбери бота → отправь `ТВОЙ-ДОМЕН` (без `https://`).
3. В Vercel добавь `TELEGRAM_BOT_TOKEN` = токен. Redeploy.

Заметки: у бота один домен; `localhost` BotFather не принимает — для локальной
разработки используй туннель (ngrok / cloudflared) и отдельного тестового бота.
Токен никому не показывай (он только на сервере).

### 2. GitHub (~3 минуты)

1. GitHub → **Settings → Developer settings → OAuth Apps → New OAuth App**.
2. Homepage URL: `https://ТВОЙ-ДОМЕН`
   Authorization callback URL: `https://ТВОЙ-ДОМЕН/api/auth/callback/github`
3. После создания скопируй **Client ID**, нажми **Generate a new client secret** и скопируй секрет.
4. В Vercel: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`. Redeploy.

У одного приложения один callback-URL. Для локальной разработки создай второе
приложение с callback `http://localhost:3000/api/auth/callback/github`.

### 3. Google (~5 минут)

1. Открой [Google Cloud Console](https://console.cloud.google.com/) → создай проект (бесплатно, карта не нужна).
2. **APIs & Services → OAuth consent screen** (в новом интерфейсе — *Google Auth Platform*): тип **External**, название приложения, твоя почта поддержки и контактная почта.
3. Статус публикации переведи в **In production** (кнопка *Publish app* / раздел *Audience*). Для входа нужны только базовые данные профиля (`openid`, `profile`), поэтому проверка Google не требуется. Пока приложение в режиме *Testing*, войти смогут только добавленные тестовые пользователи.
4. **Credentials → Create credentials → OAuth client ID → Web application**. В *Authorized redirect URIs* добавь:
   `https://ТВОЙ-ДОМЕН/api/auth/callback/google`
   (для локальной разработки можно добавить и `http://localhost:3000/api/auth/callback/google`).
5. Скопируй **Client ID** и **Client secret** → в Vercel: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`. Redeploy.

### Если что-то не работает

| Симптом | Причина |
|---------|---------|
| Нет кнопки провайдера | Не заполнены его переменные или нет `AUTH_SECRET`; не сделан Redeploy |
| `redirect_uri_mismatch` (Google) / «redirect_uri is not associated» (GitHub) | Callback в консоли сервиса не совпадает с `https://ТВОЙ-ДОМЕН/api/auth/callback/...` символ в символ; на превью-деплоях домен другой — задай `SITE_URL` или входи только на основном домене |
| Telegram: «Bot domain invalid» | Не выполнен `/setdomain` или домен указан с `https://` |
| Telegram-окно открывается и закрывается | Токен в `TELEGRAM_BOT_TOKEN` от другого бота, чем тот, которому задан домен |
| «Сессия входа устарела» | Cookie блокируется браузером или прошло более 10 минут между нажатием и подтверждением |
| Google: «Access blocked: app not verified» | Приложение в режиме *Testing* — переведи в *In production* |

### Для тех, кто форкает репозиторий

Создай **свои** приложения/бота по инструкциям выше и пропиши собственные переменные
в своём проекте Vercel — чужие ключи и домены переиспользовать нельзя.
Для локального запуска скопируй `.env.example` в `.env.local` и заполни.

## Общий аккаунт с ботом

Сайт и [бот Kulsh](https://github.com/starfall-apk/kulsh) используют один аккаунт,
один баланс, один дневной usage и одни API-ключи. Источник правды — Upstash Redis,
который уже подключён для синхронизации чатов.

| Ключ | Что хранит |
|------|------------|
| `kulsh:acct:{id}` | аккаунт: привязанные способы входа, имена, аватары |
| `kulsh:ident:{identity}` | `google:<sub>` / `github:<id>` / `tg:<telegram id>` / `ds:<discord id>` → аккаунт |
| `kulsh:merged:{old}` | редирект со старого аккаунта после слияния |
| `kulsh:u:{id}:balance` | баланс в копейках |
| `kulsh:u:{id}:topup`, `:topupcount` | всего пополнено и число пополнений |
| `kulsh:u:{id}:bonus` | бонус к следующему пополнению, % |
| `kulsh:u:{id}:usage:{YYYY-MM-DD}` | токены за день |
| `kulsh:u:{id}:apikeys`, `kulsh:key:{sha256}` | API-ключи и быстрый поиск по ключу |

### Привязка

В меню аккаунта → **Способы входа** → **Привязать**:

- **Google / GitHub** — обычный OAuth в режиме привязки; после возврата сайт
  показывает предупреждение и подтверждение.
- **Telegram** — вход через виджет сразу попадает в аккаунт `tg:<id>`, тот же,
  что у бота. Если виджет не может доставить подтверждение (домен не задан,
  запрос «Принять» не приходит), используй **код из бота**: в боте `/profile` →
  **🔗 Привязать аккаунт** выдаёт 8-символьный код на 15 минут, его можно ввести
  и в окне входа, и в окне привязки.

Если у выбранного способа уже есть отдельный аккаунт с балансом, слияние **не
происходит молча**: сначала показываются оба баланса и сумма, затем подтверждение.
После слияния балансы и сумма пополнений складываются, usage за день берётся
максимальный, API-ключи объединяются (до 10), старые сессии продолжают работать.

### Платные модели

Модели с пометкой 💳 (`grok-4.7`, `claude-sonnet-5-5`, `claude-opus-5-5`,
`claude-fable-5-1`, `gpt-6-astra`, `qwen3.8-max-0902`) списывают деньги с общего
баланса по тем же ценам, что в боте (`api/_models.js` → `PRICING`). Если баланс
равен нулю, запрос отклоняется с понятным сообщением. Деньги списываются только
после успешного ответа; при обрыве на стороне сервиса — не списываются.

### [OI]-совместимый API

Для IDE, клиентов и любых инструментов, где можно добавить [OI]-совместимого
провайдера:

| Параметр | Значение |
|----------|----------|
| Base URL | `https://kulsh.vercel.app/v1` |
| Chat | `POST /v1/chat/completions` |
| Models | `GET /v1/models` |
| Ключ | `Authorization: Bearer kulsh_sk_...` (или `api-key`, `x-api-key`) |

Поддерживаются `stream: true` (SSE с `data: [DONE]`), `stream: false` (обычный
JSON), `content` строкой или массивом частей (`text` + `image_url`), а также
`GET /v1/models` в формате `{"object":"list","data":[...]}`. Старый нативный
эндпоинт `POST /api/v1/chat` остался для обратной совместимости.

### Пополнение и промокоды на сайте

В меню аккаунта виден тег `ID<telegram id>` и ссылка на DonationAlerts — тег берётся
из привязанного Telegram, поэтому деньги сразу попадают на общий баланс. Если Telegram
не привязан, кнопка ведёт в привязку. Промокоды вводятся там же: **Промокод** в меню
аккаунта. Они общие с ботом (`kulsh:promo:*`), включая бонус к следующему пополнению.

## Модели

Модели и их параметры заданы в **двух местах**, которые нужно менять синхронно:
- `api/_models.js` — серверный реестр (источник истины для лимитов и валидации);
- `public/app.js` → `MODELS` — список для интерфейса (иконки, описания, группировка по провайдеру).

| ID                     | Провайдер    | Зрение | Множ. | Название |
|------------------------|--------------|:------:|:-----:|----------|
| `gemini-2.5-flash`     | google       |   ✓    | 1     | Gemini 2.5 Flash |
| `gemini-2.5-flash-lite`| google       |   ✓    | 1     | Gemini 2.5 Flash Lite |
| `gemini-3.5-flash`     | google       |   ✓    | 1.5   | Gemini 3.5 Flash |
| `gemini-3.5-flash-lite`| google       |   ✓    | 1.5   | Gemini 3.5 Flash Lite |
| `gemini-3.6-flash`     | google       |   ✓    | 3     | Gemini 3.6 Flash |
| `gemini-3.7-flash`     | google       |   ✓    | 3     | Gemini 3.7 Flash |
| `gemini-3.8-flash`     | google       |   ✓    | 3     | Gemini 3.8 Flash |
| `deepseek-v4.1-flash`  | neutralbeats |   ✓    | 1     | DeepSeek V4.1 Flash |
| `deepseek-v4-pro`      | neutralbeats |   ✗    | 2     | DeepSeek V4 Pro |
| `glm-5.3-flash`        | neutralbeats |   ✓    | 1     | GLM 5.3 Flash |
| `kimi-k3`              | neutralbeats |   ✓    | 3     | Kimi K3 |

- `provider` — какой адаптер использовать (`api/_providers.js`).
- `vision` — принимает ли модель изображения. У моделей с `vision: false`
  (сейчас это `deepseek-v4-pro`) вложения-картинки блокируются и на клиенте,
  и на сервере.
- `mult` — множитель расхода дневного лимита (в токенах) за запрос. Лёгкие
  модели ×1, флагманы — дороже (до ×3).

Гость без входа ограничен одной моделью — `gemini-3.5-flash-lite`
(`GUEST_MODEL` в `api/_models.js`).

## Провайдеры

`api/_providers.js` описывает единый контракт, чтобы `api/chat.js` не знал
деталей сервисов:

- `keys(env)` — список ключей провайдера для ротации;
- `open(ctx)` — `Promise<Response>` со стримом;
- `parseEvent(data)` — разбор одного SSE-события в `{ text, finish, blocked, usage }`.

`chat.js` нормализует поток и шлёт клиенту события `{ delta }` / `{ done }` / `{ error }`
(плюс `{ truncated: true }`, если ответ оборвался по таймауту, и `{ recall: true }`).

**Тайминги.** У Vercel Edge лимит 25 с только на *время до первого байта*; сам
стрим может длиться до 300 с. Поэтому в `chat.js` две фазы: `OPEN_BUDGET_MS = 22 000`
(ротация ключей до первого ответа) и `STREAM_BUDGET_MS = 280 000` (сам стрим).
Плюс idle-таймаут `IDLE_MS = 60 000` — если апстрим молчит, соединение обрывается.
Лимит вывода модели — 16 384 токена (`maxOutputTokens` / `max_tokens`).

**Google Gemini** — нативный `streamGenerateContent`, ключи `APIKEY1..APIKEY5`.
**NeutralBeats** — [OI]-совместимый `/chat/completions`, ключ `NEUTRALBEATS_API_KEY`,
текстовые вложения инлайнятся в промпт, изображения — как `image_url` (data URL).

### Если модель не отвечает

В логах Vercel (`[chat] ...`) видно, что именно произошло:

| Запись в логе | Что значит | Что делать |
|---------------|------------|------------|
| `result: 'no-key'` | Не задан ключ провайдера | Добавь `APIKEY1..` или `NEUTRALBEATS_API_KEY` и сделай Redeploy |
| `result: 'timeout'` | Провайдер не ответил за 6 с | Чаще всего перегрузка/лимит; попробуй другую модель |
| `result: 'http:404'` | Модель недоступна для этих ключей | Проверь ID модели (см. таблицу выше) |
| `[chat] empty-response` | Стрим открылся, но текста не пришло | В логе рядом теперь есть `diag` (`ctype`, `dataLines`, `events`, `head`) — по нему видно, что вернул сервис |

`diag.head` в `empty-response` содержит первые 400 символов ответа провайдера —
это помогает понять, пришёл ли не-стриминговый JSON, reasoning-контент или что-то ещё.

## Системный промпт

Системная инструкция для модели зашита в `api/chat.js` (`SYSTEM_PROMPT`).
Меняется прямо там — без пересборки фронтенда.

## Хранение чатов и настроек (по аккаунту)

Чаты и настройки залогиненного пользователя сохраняются на сервере и подтягиваются
на любом устройстве (`api/sync.js` + `public/sync.js`). localStorage остаётся быстрым
кэшем. Конфликты решаются «последняя правка побеждает» отдельно по каждому чату.
Для **хранения** вложения (фото/файлы, base64) не сохраняются — только текст чатов
(в сам запрос к модели вложения уходят, см. «Провайдеры»).
Гость (без входа) хранит всё только в браузере. При первом входе чаты из браузера
переносятся в аккаунт; при выходе локальная копия чатов удаляется.

**Подключение базы (один раз):** Vercel → проект → **Storage** → **Create / Marketplace →
Upstash Redis** (есть бесплатный тариф) → **Connect Project**. Vercel сам добавит
`KV_REST_API_URL` и `KV_REST_API_TOKEN` (годятся и `UPSTASH_REDIS_REST_URL` /
`UPSTASH_REDIS_REST_TOKEN`). После этого сделай **Redeploy**. Без базы сайт работает
как раньше — чаты только в браузере, а лимиты не действуют (см. ниже).

Всё общение с базой идёт через `api/_store.js` — тонкую прослойку над Upstash REST.
Хранилище при желании можно заменить (например, на Postgres), не трогая бизнес-логику.

## Лимиты и Usage

Один общий суточный лимит **в токенах** на аккаунт (общий и для чата, и для будущего API).
Каждая модель «тратит» его по-разному (поле `mult` в `api/_models.js`).

| Кто              | Лимит                          | Модели |
|------------------|--------------------------------|--------|
| Гость (без входа)| 15 000 токенов/сутки           | только `gemini-3.5-flash-lite` |
| Залогиненный     | 100 000 токенов/сутки          | все модели |

Стоимость запроса = `(входные + выходные токены) × mult`. Если провайдер вернул
точный `usage` — берём его, иначе токены оцениваются по длине текста (~3.5 символа
на токен).

- Сброс — в полночь по **UTC** (не по локальному времени).
- Списание делается **только после успешного ответа**; при ошибке на стороне
  сервиса или обрыве клиентом токены не списываются.
- Баланс (`kulsh:u:{id}:balance`) — задел под будущие платные тарифы, пока 0.

Ключи в Redis (`api/_usage.js`):

```
kulsh:u:{id}:usage:{YYYY-MM-DD}   → INCRBY, TTL 2 суток (само сбрасывается)
kulsh:u:{id}:balance              → целое (задел под платные тарифы)
kulsh:g:{guestId}:usage:{day}     → то же для гостя
```

Идентификатор гостя хранится в подписанной cookie `kulsh_guest`
(`AUTH_SECRET` используется как секрет подписи). Состояние лимита доступно
через `GET /api/usage` → `{ enabled, used, limit, unit, resetsAt, balance, guest }`.
Если база не подключена, `enabled: false` и лимит не применяется — сайт
продолжает работать.

Константы лимитов — в `api/_usage.js`: `GUEST_TOKEN_LIMIT = 15000`, `USER_TOKEN_LIMIT = 100000`.

## Скиллы

Скилл — это markdown-инструкция, которая добавляется к системному промпту
(поле `skillsPrompt` в `/api/chat`). Скиллы **не включаются заранее** — их
вызывают прямо в сообщении через `@`:

- набери `@` в поле ввода — появится список скиллов (личные + встроенные);
- выбери нужный (стрелки/Enter или клик) — в текст подставится `@id`;
- при отправке сервер получает содержимое только этих скиллов.

- **Встроенный каталог** — статика в репозитории: `public/skills/manifest.json`
  и `public/skills/*.md` (coder, editor, teacher, translator, analyst).
  Правь файлы напрямую — пересборка не нужна.
- **Личные скиллы** — добавляются в интерфейсе, можно загрузить готовый
  `SKILL.md` (из него извлекается тело и frontmatter `name`/`description`).
  Хранятся в Redis (`api/skills.js`): не более 20 штук, название ≤ 60 символов,
  текст ≤ 20 000. Требуется вход; у гостя личных скиллов нет.
- У каждого скилла есть **название** (с пробелами) и **id** для вызова через `@`.
  В id допустимы буквы (в т.ч. кириллица), цифры, `_ - .` — без пробелов и
  символов `@ / :`.
- Клик по скиллу в диалоге открывает превью с отрисовкой markdown.

```
GET    /api/skills            → { skills: [{ id, title, desc, content, createdAt }] }
POST   /api/skills  {id, title, desc, content} → { skill }
DELETE /api/skills?id=...     → { ok: true }
```

Ключ в Redis: `kulsh:u:{id}:skills`.

## Голосовой чат

Голосовой ввод (распознавание речи) и озвучка ответов работают через
встроенные браузерные Web Speech API — бесплатно, без ключей, но
качество и доступность голосов зависят от браузера пользователя
(лучше всего работает в Chrome).

## Публичный API

Публичный API работает на том же ядре, что и веб-чат (`api/_chat-core.js`), и делит
с ним дневной лимит. Базовый адрес: `https://kulsh.vercel.app/api/v1`.

Аутентификация — заголовок `Authorization: Bearer <API_KEY>`. Ключ создаётся в
аккаунте: меню аккаунта (аватар) → **API**. Сам ключ показывается один раз; в базе
хранится только его SHA-256 хеш (`api/_apikeys.js`), поэтому утечка Redis не даёт
доступа к API. У аккаунта до 10 ключей.

| Метод и путь        | Что делает |
|---------------------|------------|
| `POST /api/v1/chat` | стримит ответ модели (SSE) |
| `GET  /api/v1/models` | список моделей: `id`, `provider`, `vision`, `mult`, `name` |
| `GET  /api/v1/usage` | состояние дневного лимита аккаунта |

Пример:

```bash
curl -N https://kulsh.vercel.app/api/v1/chat \
  -H "Authorization: Bearer kulsh_sk_..." \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-v4.1-flash","messages":[{"role":"user","content":"Привет!"}]}'
```

Ответ — поток `data: {...}`:

```
data: {"delta":"Привет"}
data: {"delta":", чем помочь?"}
data: {"done":true,"usage":{"used":12430,"limit":100000,"unit":"tokens","cost":52}}
```

Предполётные ошибки публичного API отдают честные HTTP-статусы (веб-чат на те же
ситуации отвечает SSE-событием `{error}`, потому что ждёт поток):

| Статус | `error` | Когда |
|--------|---------|-------|
| `401` | `missing_key` / `invalid_key` | нет ключа или он недействителен/отозван |
| `400` | `bad_json` / `empty_request` / `vision_not_supported` | плохой запрос |
| `402` | `limit_exceeded` | исчерпан дневной лимит и нулевой баланс |
| `502` | `upstream_unavailable` | модель временно недоступна (токены не списываются) |
| `503` | `no_keys` | на сервере не заданы ключи провайдеров |

Управление ключами (для интерфейса, по сессии):

```
GET    /api/keys            → { enabled, keys: [{ id, name, prefix, createdAt, lastUsed }] }
POST   /api/keys  {name}    → { key, secret }   (secret — один раз)
DELETE /api/keys?id=...     → { ok: true }
```

Ключи в Redis: `kulsh:u:{id}:apikeys` (список) и `kulsh:key:{hash}` → userId.

## Локальная разработка

```bash
npm i -g vercel
vercel dev
```

Так функции из `api/` будут доступны локально на `http://localhost:3000/api/...`
(в т.ч. `POST /api/chat`). Для локальной разработки создай файл `.env.local`
в корне проекта с теми же переменными: `APIKEY1..APIKEY5`,
`NEUTRALBEATS_API_KEY`, `AUTH_SECRET` и (по желанию) `KV_REST_API_URL` /
`KV_REST_API_TOKEN` для проверки лимитов и скиллов.

Публичные страницы можно смотреть и без сервера, но тогда `/api/*` отдаёт 404:

```bash
python -m http.server 4173 --directory public
```


## Изменения в этой версии
- Стриминг ответа (SSE) вместо ожидания полного ответа; пустые ответы обрабатываются и показывают понятное сообщение.
- Таймаут 6 с на открытие стрима по ключу: при зависании или 429/5xx/403 сервер переходит к следующему ключу, чтобы не упираться в лимит ~25 с у Vercel. Стартовый ключ выбирается случайно, нагрузка делится между участниками.
- Ошибка 400/404 для старых моделей показывается как «модель недоступна для текущих ключей».
- Новые настройки: ширина чата, плотность, шрифт, аватарки, имена, меньше анимаций, стикер, автопрокрутка, подсказка, креативность (temperature), свои инструкции.

## v2: характер сайта
- Маскот-моаи (`mascotSVG` в app.js): три состояния — обычное (моргает), «думает» (аватар, пока ИИ отвечает) и «ошибка» (карточка с кнопкой «Повторить»). В пустом чате — анимация моаи, по тапу меняется версия.
- Шрифты локальные (`public/fonts/`): Google Sans Flex (+ Round для заголовков), Google Sans Code, иконки Material Symbols Rounded (полный набор, ~0.5 МБ). Всё предзагружается через `<link rel="preload">`. Google Sans Flex/Code не содержат кириллицу, поэтому русский текст набирается Roboto Flex / Roboto Mono. Любую иконку из набора можно использовать по имени, ничего пересобирать не нужно.
- Моно-акценты (Google Sans Code): модель, время, язык кода, счётчики, подписи.
- Чек-листы: модель пишет блок ```todo (`title:` + `- [x]`/`[~]`/`[ ]`/`[!]`). Повторный блок с тем же title обновляет первую карточку; клик по пункту меняет статус вручную.
- Формулы: KaTeX локально (`public/vendor/katex`), `$…$`, `$$…$$`, `\(…\)`, `\[…\]`, окружения `\begin{…}`.
- Вложения уходят в модель только из текущего сообщения. Маркер `!recall_media` вырезается на сервере; если модель просит старые медиа, клиент один раз повторяет запрос с последними вложениями.
- Удалены настройки аватарок, имён и стикера (всегда включены).

## v6: публичный API и правки
- Публичный API `/api/v1` (`chat`, `models`, `usage`) на общем ядре `api/_chat-core.js`
  с аутентификацией по API-ключу (`Authorization: Bearer`), честными HTTP-статусами
  и CORS.
- API-ключи создаются в аккаунте (меню → API), хранятся хешами в Redis; до 10 ключей.
- Правку сообщений ИИ убрали — редактировать можно только свои сообщения
  (у своих правка приводит к перегенерации ответа).
- Стриминг разбирается построчно независимо от `content-type`, поэтому ответ
  снова появляется постепенно даже если прокси подменил заголовок; отрисовка
  синхронизирована с кадрами, чтобы длинные ответы не подлагивали.

## Вход через Telegram — чеклист
1. `TELEGRAM_BOT_TOKEN` в Vercel (формат `123456:AA...`), `AUTH_SECRET` задан.
2. В @BotFather: `/setdomain` → выбери бота → укажи **точный** домен сайта без `https://` (например `kulsh.vercel.app`). Без этого Telegram не присылает код.
3. Открывай сайт по тому же домену (не preview-URL Vercel) и разреши всплывающие окна.

## Политика конфиденциальности
Текст — `public/privacy/index.html` (проверь и поправь под себя). Согласие хранится в `localStorage` (`kulsh.privacy.v1`); при смене текста измени `POLICY_VER` в `public/auth.js`, чтобы запросить согласие заново.
